# Награды — пороги по ролям, редактируемые на сайте

Дата: 2026-07-23
Статус: одобрено пользователем в чате, ожидает записи в план реализации.

## Контекст

Это первый из нескольких независимых подпроектов в рамках более крупного
запроса (кружки, вход участников на сайт, детали дуэлей, профили, система
«нью» — идут отдельными спеками).

Система наград (медали, 8 степеней) уже реализована:
- `schema.sql:265-281` — таблицы `rewards` (кто/кому/степень/причина) и
  `reward_degree_levels` (степень → минимальный уровень доступа, с
  `updated_by`/`updated_at`).
- `bot.py:12960-13035` — `_default_reward_degree_level()` (дефолтные пороги),
  `required_reward_level()` (дефолт + оверрайд из БД), команда
  `право степень N уровень` (`_handle_reward_degree_permission`) — меняет
  порог, доступно любому, кто уже имеет нужный уровень (не только владельцу).
- `bot.py:451, 640` — кэш `reward_degree_level_overrides`, грузится при
  старте бота из `db.list_reward_degree_levels()`.
- `bot.py:3428-3464` — `panel_action_reload_loop`: раз в 10 сек проверяет флаг
  `bot_data.panel_action_reload`, при изменении перечитывает несколько кэшей,
  включая `command_level_overrides` — образец для того же самого с наградами.
- `webpanel/app.py:1206-1209` — `_signal_action_reload()`: панель поднимает
  этот флаг после любой правки, которую должен подхватить бот без рестарта.
- Сайт уже показывает похожий UI для порогов команд — вкладка «Дерево
  команд» (`webpanel/static/index.html:149`, JS —
  `webpanel/static/app.js:1044-1106`, `GET /api/command-tree`,
  `POST /api/command-tree/level`).
- Роли аккаунтов панели: `ROLE_OWNER`/`ROLE_ADMIN` (`STAFF_ROLES`) +
  `ROLE_MEMBER` (`webpanel/auth.py:47`, `require_owner` на строке 206).

Текущие дефолтные пороги (без оверрайдов): степень 1-2 → модератор
(`LEVEL_MODERATOR=1`), 3-5 → админ (`LEVEL_ADMIN=2`), 6-8 → старший
(`LEVEL_SENIOR=3`). Это не совпадает с желаемым распределением.

## Требование

- Модератор может выдавать награды по степень **3** включительно.
- Администратор — по степень **4** включительно.
- Старший администратор — по степень **5** включительно.
- Степени **6-8** — только владелец (`OWNER_LEVEL=99`; в БД сохраняем то же
  число, что использует существующий механизм оверрайдов).
- Эти пороги можно менять **на сайте**, и менять их там могут **только
  владельцы** (более строго, чем в самой бот-команде, которую не трогаем —
  см. «Не в скобо» ниже).
- В хелпе бота («награды») должно быть написано про новые пороги и про то,
  что их можно поменять на сайте.

## Дизайн

### 1. Новые дефолты (`bot.py`)

```python
def _default_reward_degree_level(degree: int) -> int:
    if degree <= 3:
        return LEVEL_MODERATOR
    if degree == 4:
        return LEVEL_ADMIN
    if degree == 5:
        return LEVEL_SENIOR
    return OWNER_LEVEL
```

Действует только там, где ещё нет строки-оверрайда в `reward_degree_levels`
(старое поведение сохраняется для чатов, где пороги уже настроены вручную —
это ожидаемо и не требует миграции: `required_reward_level()` и так сначала
смотрит в `reward_degree_level_overrides`).

### 2. Сайт: новый блок в вкладке «Дерево команд»

Не отдельная вкладка — карточка «🎖 Пороги наград» в существующем экране
`cmdtree`, сразу под списком команд (тот же паттерн UI: подпись степени +
эмодзи, выпадающий список уровня, кнопка сброса при оверрайде).

**Backend (`webpanel/app.py`)**
- `GET /api/reward-levels` — `Depends(auth.require_user)` (владелец и админ
  панели видят пороги). Ответ:
  ```json
  {
    "degrees": [
      {"degree": 1, "emoji": "🎗", "level": 1, "overridden": false},
      ...
      {"degree": 8, "emoji": "🏵", "level": 99, "overridden": false}
    ],
    "level_names": {"1": "🛡 Модератор", "2": "⭐ Администратор", "3": "👑 Старший администратор", "99": "🔱 Владелец"},
    "can_edit": true
  }
  ```
  `level` — оверрайд из `db.list_reward_degree_levels()`, иначе дефолт из
  копии `_default_reward_degree_level`, которую нужно продублировать в
  `webpanel/roles.py` рядом с уже существующими там `LEVEL_MODERATOR` /
  `LEVEL_ADMIN` / `LEVEL_SENIOR` / `OWNER_LEVEL` / `DEFAULT_LEVEL_NAMES`
  (`webpanel/roles.py:27-40` — панель не импортит `bot.py`, см. память
  `panel-cannot-import-bot`, поэтому эти константы там уже задублированы
  из `bot.py` с комментарием-напоминанием «поправьте и тут», строка 14).
  `can_edit` = `user.role == "owner"`.
- `POST /api/reward-levels/level` — `Depends(auth.require_owner)`. Тело
  `{"degree": int, "level": int|null}` (`null` = сброс на дефолт).
  Валидация: `degree` в 1..8, `level` в `{1, 2, 3, 99}` либо `null`.
  Пишет через уже существующие `db.set_reward_degree_level(degree, level,
  updated_by=user.tg_user_id или user.id)` / `db.reset_reward_degree_level`,
  затем `await _signal_action_reload()`.

**Бот (`bot.py`)** — в `panel_action_reload_loop` (строка ~3450-3460)
добавить после блока с `command_level_overrides`:
```python
reward_degree_level_overrides.clear()
reward_degree_level_overrides.update(await db.list_reward_degree_levels())
```
Правки на сайте долетают до бота без рестарта в течение
`PANEL_RELOAD_INTERVAL` (10 сек) — то же самое поведение, что уже есть для
порогов команд.

**Frontend (`webpanel/static/`)**
- `index.html`: новая карточка внутри `#view-cmdtree` (после списка команд),
  контейнер `#reward-levels-body`.
- `app.js`: `loadRewardLevels()` / `renderRewardLevels()` /
  `rewardSetLevel(degree, level)` — по образцу
  `loadCommandTree/renderCommandTree/cmdSetLevel` (`app.js:1047-1102`).
  Вызывать `loadRewardLevels()` там же, где сейчас `loadCommandTree()`
  (`app.js:1033`).
  Для не-владельца (`can_edit=false`) — как и в дереве команд, вместо
  `<select>` просто чип с текущим уровнем, без кнопки сброса.

## Не в скобо (сознательно не делаем)

- Саму команду `право степень N уровень` **не** делаем владелец-only — она
  остаётся как есть (доступна в рамках собственного уровня действующего
  админа). Более строгое ограничение (только владелец) действует только
  для правки через сайт.
- Не меняем количество степеней (остаётся 8), не трогаем сами таблицы схемы.
- Не трогаем логику самой выдачи награды (`cmd_reward`, `bot.py:13042-13123`)
  — только то, какой уровень требуется для какой степени.

## Тесты

Новый `tg-bot/tests/test_panel_reward_levels.py`:
- `GET /api/reward-levels` под ролью admin и owner — оба видят список,
  `can_edit` соответствует роли.
- `POST /api/reward-levels/level` под owner — меняет порог, ответ отражает
  новое значение, `bot_data.panel_action_reload` обновился.
- `POST /api/reward-levels/level` под admin — 403.
- `POST` со степенью вне 1-8 или уровнем не из `{1,2,3,99,null}` — 400.
- Сброс (`level: null`) возвращает дефолт по новой формуле (3→модератор,
  4→админ, 5→старший, 6-8→владелец).
