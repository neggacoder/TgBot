# Настройки чатов в веб-панели (подпроект П1)

Дата: 2026-07-28

**Статус: выполнено.** Все 7 задач плана реализованы: реестр настроек
(`chat_settings.py`), сторож границ, слой хранения в `db.py`, права панели по
уровню в боте, API `/api/chat-settings`, вкладка «Настройки чата» в
интерфейсе и абзац в справке бота (`help_texts.py`, раздел «Настройка»).

## Задача

Перенести на сайт то, что сегодня настраивается только командами в чате.
Общая задача — 61 команда админского уровня в 15 категориях — на одну спеку не
делится, поэтому разбита на четыре подпроекта. Здесь описан первый.

## Деление на подпроекты

| | Что | Состояние |
|---|---|---|
| **П1** | Каркас: права по уровню в боте, реестр настроек, автоформа. Скалярные настройки чата | **эта спека** |
| П2 | Списочные настройки: магазин чата, ЧС банка, каталог питомцев, заявки рынка | позже |
| П3 | Разовые действия: «чат сюда», сбросы, выдачи, `clearUsers` | позже |
| П4 | Мелочи: хранилище, модерация закладок/кланов/кружков, темы, правила | позже |

П1 идёт первым не по важности: П2–П4 переиспользуют его выбор чата, проверку
прав и слой хранения. Без него каждая следующая страница изобретала бы своё.

## Границы

**Входит:** админские настройки чата, которые являются одним значением —
число, переключатель или выбор из списка.

**Не входит:** модерация людей, игровые действия участников, списки и разовые
действия. Команды в боте остаются как есть: сайт добавляется рядом, а не
вместо.

## Что уже есть

Панель — FastAPI (`webpanel/app.py`, 123 маршрута) плюс обычный JS без сборки
(`webpanel/static/app.js`). В ней уже настраиваются: фильтр слов, дерево
команд, ивенты чата, биржа, уровни наград, роли чата, РП-действия, жесты,
жалобы, варны, ресты, ТГ-админы и общие настройки бота.

Два моста между ботом и панелью уже проложены, изобретать нечего:

* бот публикует свой реестр команд в таблицу `command_registry`, панель читает
  её через `db.list_command_registry()`;
* чистые модули (`rest_rules`) панель импортирует напрямую — она отдельный
  процесс и `bot.py` импортировать не может, это подняло бы второго бота.

## Найденные ограничения

Проверено по коду до начала работы.

**Уровни админов в боте глобальные.** Таблица `admins` — это `(user_id,
level)`, без `chat_id`; проверка — `has_level(user_id, min_level)`. Уровни
команд тоже глобальны: `command_permissions(command_key, min_level)`. Значит
«модератор в чате X» как понятие в боте не существует. Делать уровни
початовыми — отдельный проект крупнее всего переноса настроек; решение
принято: сайт подчиняется существующему глобальному уровню.

**Управление чужими аккаунтами уже закрыто.** `/api/users` требует владельца,
`POST /api/password` меняет пароль только себе (`user.id`). Отдельной работы
не требует.

**Настоящая дыра — панельная роль в обход уровня.** Роли панели
(`owner`/`admin`/`member`) живут отдельно от уровня в боте. Панельный `admin`
дёргает все админские эндпоинты независимо от того, какой у него уровень в
боте, — хоть нулевой. Человек-модератор с панельным аккаунтом `admin` получает
на сайте больше, чем в чате. Это и чиним.

**Хранилищ настроек три, а не одно.** Проверено: часть настроек лежит в
колонках початовых таблиц (`bank_settings`, `market_settings`,
`stock_settings`, `marriage_settings`, `economy_settings`), часть — в
key-value таблице `data` (норма — ключ `norm:{chat_id}`, боссы — `_boss_off_key`,
автоотказ банка — `bank_autoreject:{chat_id}`), часть — в глобальной строке
`settings` (`duel_outcome`). Реестр обязан поддерживать все три, иначе треть
настроек уедет в «исключения».

## Раздел 1. Сайт подчиняется уровню в боте

Новый модуль `webpanel/permissions.py`:

* `async def bot_level(user: PanelUser) -> int` — уровень человека в боте:
  `OWNER_IDS` → 99, иначе уровень из `db.get_admin(user.tg_user_id)`. Аккаунт
  без привязки к Telegram (`tg_user_id is None`) → 0.
* `async def required_level(command_key: str) -> int` — override из
  `command_permissions`, иначе `default_level` из `command_registry`. Формула и
  источники ровно те же, что у `bot.required_level`, — расходиться нечему.
* `async def ensure(user, command_key) -> None` — 403 с названием нужного
  уровня, если не дотягивает.

Панельная роль остаётся ровно для одного: управления аккаунтами самой панели
(создание пользователей, журнал входов). Всё, что делает бот, гейтится
уровнем в боте.

**Ломающее изменение.** Панельный `admin` без привязки к Telegram потеряет
доступ к новым эндпоинтам, пока не привяжет аккаунт (`POST /api/link-telegram`
уже существует). Владелец — из `OWNER_IDS` или с панельной ролью `owner` —
сохраняет полный доступ всегда: иначе владелец может запереть себя снаружи.

В П1 новая проверка применяется только к новым эндпоинтам настроек чата.
Переводить на неё существующие 123 маршрута — отдельная работа: это сломало бы
доступ у действующих пользователей панели без предупреждения.

## Раздел 2. Реестр настроек — `chat_settings.py`

Чистый модуль без БД и Telegram, как `pets.py` и `farming.py`. Импортируется и
панелью, и (для сверки) тестами бота.

```python
STORAGE_COLUMN = "column"     # колонка початовой таблицы
STORAGE_DATA = "data"         # ключ в key-value таблице data
STORAGE_SETTINGS = "settings" # колонка глобальной строки settings

KIND_NUMBER = "number"
KIND_BOOL = "bool"
KIND_CHOICE = "choice"

@dataclass(frozen=True)
class Setting:
    key: str            # "bank.rate_1d" — устойчивый ключ для API
    group: str          # "Банк" — заголовок блока в форме
    command_key: str    # "bank_manage" — отсюда требуемый уровень
    title: str
    kind: str
    storage: str
    target: str         # имя таблицы, шаблон ключа data или имя колонки settings
    column: str = ""    # для STORAGE_COLUMN
    default: object = None
    minimum: float | None = None
    maximum: float | None = None
    choices: tuple[tuple[str, str], ...] = ()   # (значение, подпись)
    hint: str = ""
```

Плюс функции модуля: `BY_KEY`, `GROUPS` (порядок блоков), и
`validate(setting, raw) -> object` — приводит строку из формы к нужному типу
или бросает `ValueError` с человеческим русским текстом.

### Инвентарь П1

23 настройки, 12 команд. (Раньше в разговоре звучало «~35» — это была оценка до
разбора; после сверки с кодом остальные админские команды оказались списками и
разовыми действиями, то есть П2–П4.)

| Группа | Настройки | Команда | Хранение |
|---|---|---|---|
| Банк | `rate_1d`, `rate_3d`, `rate_7d`, `credit_fee_percent`, `credit_term_days`, `credit_penalty_percent`, `min_deposit` | `bank_manage` | `bank_settings` |
| Банк | автоотказ по кредитам | `bank_auto_reject_toggle` | `data` |
| Рынок | `mode`, `commission_percent`, `max_price`, `max_goods` | `market_manage` | `market_settings` |
| Биржа | `min_change_percent`, `max_change_percent`, `dividend_percent` | `stock_settings` | `stock_settings` |
| Биржа | `enabled` | `stock_toggle` | `stock_settings` |
| Брак | `renew_price`, `divorce_mode`, `rating_enabled` | `marriage_price_set`, `marriage_mode_set`, `marriage_rating_toggle` | `marriage_settings` |
| Ферма | `farm_yield` | `farm_yield_set` | `economy_settings` |
| Активность | недельная норма | `set_norm` | `data` (`norm:{chat_id}`) |
| Боссы | боссы включены | `boss_toggle` | `data` |
| Дуэли | исход проигрыша | `duel_outcome` | `settings` (глобальная) |

Ивенты чата (`chat_events_toggle`) в инвентарь не входят: в панели уже есть
`/api/chat-events`. Часовой пояс и срок автоочистки — уже в общих настройках.

`duel_outcome` глобальный, а не початовый; в форме помечается подписью
«действует во всех чатах», иначе правка в одном чате незаметно изменит все.

### Про две правды о границах

Реестр объявляет `minimum`/`maximum`/`default`, но у обработчиков бота своя
проверка. Разойдутся — сайт и чат начнут принимать разные значения.

Переписывать обработчики бота в П1 не будем: слишком много изменений за раз.
Вместо этого — тест, сверяющий константы бота с реестром (по образцу
`farming.FOOD_ITEM_KEY == pets.FOOD_ITEM_KEY`). Расхождение падает на прогоне,
а не всплывает у пользователя.

## Раздел 3. Слой хранения в `db.py`

Три функции, по одной на вид хранения, и две обёртки над ними:

* `get_chat_setting_values(chat_id, settings) -> dict[str, object]` — читает
  разом всё, что просят: по одному запросу на таблицу, а не по запросу на поле.
* `set_chat_setting_value(chat_id, setting, value) -> None` — запись с
  апсертом строки чата.

Общий слой возможен потому, что все початовые таблицы настроек устроены
одинаково: «строка чата или значения по умолчанию». Это проверено на банке,
рынке, бирже, браке и экономике.

## Раздел 4. API

Требуемый уровень зависит от настройки, а не от маршрута, поэтому зависимостью
FastAPI на маршруте это не проверить — она про ключ в теле запроса ничего не
знает. Проверка идёт внутри обработчика: `await permissions.ensure(user,
setting.command_key)`.

* `GET /api/chat-settings?chat_id=…` → `{groups: [{group, settings: [{key,
  title, kind, value, default, minimum, maximum, choices, hint, required_level,
  level_name, can_edit, global}]}]}`
* `POST /api/chat-settings` `{chat_id, key, value}` → проверка уровня,
  валидация по реестру, запись, запись в журнал через `db.add_log` с автором.

Читать список может любой сотрудник панели; править — по уровню.

## Раздел 5. Интерфейс

Новая вкладка «Настройки чата»: выбор чата из готового `/api/chats` и форма,
собранная по группам из ответа API. Стиль тот же, что в панели, — обычный JS,
без сборки и без новых зависимостей.

Поля, до которых уровень пользователя не дотягивает, показываются
**неактивными** с подписью «нужен уровень X», а не прячутся: спрятанное поле
читается как «такой настройки нет», и человек идёт спрашивать, почему сайт
беднее чата.

## Раздел 6. Ошибки

Тексты русские и человеческие, теми же формулировками, что даёт бот:

| Случай | Ответ |
|---|---|
| Неизвестный ключ настройки | 400, «Такой настройки нет» |
| Значение вне границ | 400, с указанием границ |
| Не тот тип (буквы в числовом поле) | 400, с указанием ожидаемого |
| Не хватает уровня | 403, с названием нужного уровня |
| Чат боту неизвестен | 400 |
| Аккаунт не привязан к Telegram | 403, с указанием, что привязать можно в панели |

## Раздел 7. Тесты

Три слоя.

**Реестр как чистый модуль** (`tests/test_chat_settings.py`):
ключи не повторяются; у каждой настройки `command_key` существует в
`bot.COMMAND_REGISTRY`; для `STORAGE_COLUMN` пара таблица+колонка встречается в
исходнике `db.py`; границы осмысленны (`minimum <= default <= maximum`); у
`KIND_CHOICE` значение по умолчанию входит в список; `validate` принимает
границы и отбивает выход за них.

**Сверка с ботом**: константы обработчиков совпадают с границами реестра.

**Панель через `TestClient`** (`tests/test_panel_chat_settings.py`, по образцу
`tests/test_panel_command_tree.py`): модератор не правит то, что требует
админа; владелец правит; неизвестный ключ отбивается; значение вне границ
отбивается; правка попадает в журнал; аккаунт без привязки к Telegram получает
уровень 0 и 403; владелец проходит всегда.

## Риски

1. **Ломающее изменение прав** (раздел 1) — панельные админы без привязки к
   Telegram потеряют доступ к новым разделам. Смягчение: владелец проходит
   всегда; понятный текст ошибки со ссылкой на привязку.
2. **Расхождение границ** между ботом и реестром — закрыто сторожевым тестом.
3. **Глобальный `duel_outcome`** среди початовых настроек — закрыто подписью в
   интерфейсе.
4. **`webpanel/app.py` уже 4377 строк.** Настройки чата кладём отдельным
   модулем-роутером, а не дописываем в конец: файл и так на пределе
   читаемости.
